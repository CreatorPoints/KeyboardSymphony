Getting Started

Welcome to the official technical wiki for Keyboard Symphony—a high-fidelity, cyberpunk-themed indie rhythm game built on the **Godot Engine 4** platform. Synthesizing elements of traditional lane-based music games with state-of-the-art visual scripting triggers, local cryptographic encryption, and a cloud-integrated database, the game offers a unified platform for both players and level creators.

Developed with a neon-drenched glassmorphic aesthetic (anchored by HSL-tailored cyan, magenta, and amber tones), Keyboard Symphony focuses on tight mechanical precision, reactive shader effects, and seamless profile synchronization via Supabase backend services.

Core Gameplay Mechanics

Keyboard Symphony challenges players to coordinate their keystrokes with musical rhythms flowing down a vertically oriented scrolling space. Accuracy and speed are rewarded through a multi-tiered grading structure.

Note Varieties

  1. Tap Notes (Instant Hits): Represented by glowing rectangular neon blocks. The player must strike the corresponding key at the exact moment the note intersects the bottom horizontal Hit Line.
  2. Hold Notes (Sustain Strips): Represented by elongated, translucent trails terminating in a trailing cap. The player must depress the key when the note's head contacts the Hit Line, sustain the keypress for the duration of the trail, and release it in sync with the trail's end.
    • Hold Particle Bursts: While successfully held, lanes emit continuous CPUParticles2D particle streams reflecting the lane's specific neon signature.
    • Sustain Verification: The engine handles perfect hold resolutions; if held continuously to completion, it triggers a release hitsound and awards a final score bonus.

The Judgment & Accuracy System

Accuracy is computed in real-time by subtracting the note's absolute target timestamp from the player's physical keypress time (Δt = t_press - t_target):

Accuracy Judgement Time Window (Δt) Points Awarded Visual Feedback Color
Pure Perfect ≤ ±20% of Hit Window Full 100% base score Glowing Green
Early / Late Perfect ≤ ±50% of Hit Window High 75% base score Bright Yellow / Orange
Early / Late ≤ ±100% of Hit Window Muted 50% base score Saturated Red
Miss > ±100% of Hit Window 0% points, streak breaks Blood Red
  • Sliding Neon Accuracy Meter: Positioned adjacent to the playing grid, a vertical scale featuring a dynamic Accuracy Marker slides smoothly and changes color (Green → Yellow → Red) to graphically indicate if the user hit too early (offset up) or too late (offset down).
  • Neglect Auto-Misses: If a player ignores an incoming note, the engine automatically triggers a miss judgment and frees the note once it passes beyond the miss threshold (0.18 seconds), preventing memory leaks and keeping gameplay clean.

Visual Triggers & Screen FX Overlay Engine

Drawing inspiration from dynamic visual rhythm games like Geometry Dash, Keyboard Symphony implements a robust **Visual Scripting Overlay Engine**. Level designers can insert complex screen-space shaders and scene transformations directly into level charts, synchronizing visual intensity with acoustic drops.

These visual triggers are routed through dedicated script channels on Lanes 10 to 13 and executed via specialized GLSL shaders:

The Shader Suite (assets/shaders/)

  1. Digital Glitch Shader (glitch.gdshader): Slices the screen coordinates horizontally into 30 distinct bands, shifting random bands horizontally based on a high-frequency sine-random noise generator, and performing red/blue split chromatic channel shifting.
  2. Chromatic Aberration Shader (chromatic_aberration.gdshader): Dynamically offsets the red, green, and blue color channels outward from the center, mimicking camera lens distortion.
  3. Lens Circle Vignette Shader (lens_circle.gdshader): Creates a localized dark-neon vignette tunnel. It computes pixel distances from the screen's center, keeping a specified clear_radius completely transparent, while blending a deep dark-blue quadratic falloff outwards to the corners.
  4. Pixel Inversion Shader (invert.gdshader): Performs a rapid bitwise color inversion (1.0 - Color) across all active pixels on screen.

Executable Visual Triggers

  • Sync Note Color (SNC): Targets a specific note by its ID and smoothly transitions its color to a new HSL target over a defined beat duration.
  • Screen Shake (SSH): Induces random offset displacement on the 2D game camera based on a customizable amplitude (intensity) and decay time.
  • Lens Circle (LCI): Triggers the vignette shader to snap-close around the center, hold for a defined beat length, and slowly reopen utilizing a cubic ease-in-out transition.
  • Background Color (BGC): Transitions the background canvas smoothly between custom hex colors over time.
  • Screen Flash (FLS): Floods the screen with an opaque neon color, which then fades out utilizing a quadratic ease-out decay curve.
  • Chromatic Aberration (CRA) & Glitch (GLT): Initiates high-intensity visual glitches that ease back to zero over a designated period.
  • Color Invert (INV): Flashes the pixel inversion shader, reversing all colors on screen.
  • Change Background Path (CBP): Swaps the gameplay's active background image on the fly.
  • Set Hit Sound (SHS): Swaps the game's active hitsound asset to a different sound file (e.g. a kick drum or percussion chime) mid-level.

The Professional Level Editor

Unleash your inner beat creator with our comprehensive, fully integrated Level Editor dashboard. Plotted on a vertically scrollable timeline, creators have direct control over beat snapping, metadata adjustments, and visual triggers.

Precision Grid & Subdivision Snapping

Charts are plotted on a timeline grid representing beats. To ensure absolute musical synchronization, the editor features a comprehensive Subdivision Snapping System that locks placed notes to grid lines:

  • 1/4 Snap (Quarter Beats)
  • 1/8 Snap (Eighth Beats)
  • 1/12 Snap (Triplet Snaps)
  • 1/16 Snap (Sixteenth Beats)
  • 1/24 Snap (Complex Triplets)
  • 1/32 Snap: Ultimate precision demanded for rapid mechanical drum rolls.

Dual-Operating Modes

  1. Spawn Mode: Click on any cell within the grid to instantly place a note. The editor enforces strict lane boundaries: lanes 0-9 are strictly reserved for gameplay notes, while lanes 10-13 are gated exclusively for visual triggers.
  2. Edit Mode: Click on any placed note or trigger to inspect and modify its attributes (Beat, Note length, note color, visual FX intensity, etc.) via the contextual Inspector Panel.

Real-Time Live Viewport Preview

Positioned as a glowing picture-in-picture viewport, a fully functional mini-instance of the gameplay engine runs alongside the editor!

  • Toggle previewing on to watch a simulated autoplay bot complete your chart in real-time.
  • Drag the vertical seekbar or scroll the timeline, and the viewport's camera, background audio player, and active notes instantly seek to the exact millisecond in perfect sync.

Play-As-You-Go (PAYGM) Live Recording

Recording complex streams manually can be tedious. PAYG Mode allows creators to record their chart in real-time:

  • Click the ⏺ RECORD (PAYG) button on the editor sidebar.
  • A 3-second countdown will trigger, letting you prep your hands.
  • The playback playhead starts moving. Tap keys in rhythm to place single beat notes snapped to the closest subdivision.
  • Hold a key down for longer than 0.5 beats to automatically stretch it into a glowing Hold Note until you release the key!

Audio Formats & FFmpeg Integration

To avoid latency spikes and audio playback stutters, Keyboard Symphony enforces strict OGG Vorbis audio requirements. If you select a .mp3 or .wav soundtrack, the editor initiates an automated transcode conversion pipeline.

FFmpeg Transcode Module

  1. The editor automatically prompts: "The selected audio is not in OGG format. Would you like the game to convert/rename it to .ogg automatically?"
  2. On Confirmation: The engine automatically scans local system variables and WinGet Gyan packages for an FFmpeg binary.
  3. It fires an asynchronous process call to transcode the file: ffmpeg -y -i input.mp3 -c:a libvorbis -qscale:a 5 output.ogg
  4. Upon successful transcoding, it loads the audio stream, recalculates the timeline limits, and notifies the user via global UI toasts.

Authentication & User Profile Cloud Sync

Keyboard Symphony bridges offline play with online statistics tracking through a robust database integration powered by the Supabase Backend API.

Advanced Google OAuth Listener

Players can sign in utilizing their Google credentials. The game handles this through a highly secure, custom loopback listener:

  1. The client initializes an in-game TCPServer listening on port 9999.
  2. The OS shell opens the client's default browser to the Supabase Google authorization link.
  3. Once authorized, Supabase redirects the browser to http://localhost:9999/#access_token=...
  4. The browser page runs an inline client-side JavaScript script which extracts the hash tokens and triggers a GET fetch request back to the local TCPServer before gracefully closing the browser tab.
  5. The game intercepts the HTTP headers, reads the tokens, updates the session, and triggers transition systems.

Cryptographic Profile Security

To prevent cheating, player statistics (XP, Currency, Stars, Levels Completed, and Joined Time) are saved locally in user://player_stats.json encrypted using **AES-256 (Advanced Encryption Standard)** with a highly secure 32-character passkey. If a player attempts to edit their local statistics, the decryption process fails, protecting leaderboard integrity.

Account Verification & The Verified Badge

The game features a multi-tiered account validation system. Unlocking a glowing Verified Badge (a stylized cyan cyber tag border overlay) on the profile screen requires the player to satisfy two requirements:

  • Email Verification: Confirming their registered email address (players can request a verification link directly from the Profile UI).
  • Google Linkage: Linking their third-party Google Account.

Completing verification unlocks a unique, database-indexed Member ID (PID) which displays on their profile card (e.g. MEMBER #0024).

Core Systems & Autoload Architecture

Underpinning the user interface and game loop are three core autoload singletons that handle game states, visual effects, and audio binds dynamically.

🔊 SoundManager (src/core/sound_manager.gd)

A procedural audio generation module that synthesizes all user interface sounds dynamically in system memory on boot, eliminating static audio file sizes:

  • Hover Sound: A high-frequency sine-frequency sweep up: 600Hz → 900Hz over 0.04s.
  • Press Sound: A crisp retro mechanical click sweep down: 500Hz → 150Hz over 0.07s.
  • Success Bell: A gorgeous major-chord chime combining three harmonious sine frequencies (880Hz, 1109.73Hz, 1318.51Hz) decaying exponentially over 0.45s.
  • Error Buzzer: A low digital alarm blending sine waves with high-grit square waves.
  • Automatic UI Sound Binding: On boot and whenever a new scene is loaded, the SoundManager intercepts node addition signals (get_tree().node_added) and automatically binds hover/press sound effects to all BaseButton nodes recursively, guaranteeing game-wide audio responsiveness with zero manual wiring!

ToastManager (src/core/toast_manager.gd)

A premium global notification overlay layer running at layer 128 (on top of all menus and transitions). It spawns glassmorphic, glowing alerts that stack vertically and feature cubic scaling animations. When a toast expires, the container collapses its boundaries using tweens, allowing remaining alerts to slide into place smoothly.

🌅 SceneTransition (src/core/scene_transition.gd)

A system-wide scene switcher operating on canvas layer 100. When transitioning, a massive diagonal neon panel swipes across the viewport accompanied by a stereo transition whoosh WAV sound effect. The panel cycles its solid color through a spectrum of vibrant neon HSL coordinates (Cyan → Magenta → Orange → Green → Hot Pink) with a high-intensity glow edge.
